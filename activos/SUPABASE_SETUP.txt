ICSSA — SUPABASE MULTIUSUARIO Y CARGA CENTRAL

1) Ejecutar supabase-schema.sql en Supabase SQL Editor.
2) En Project Settings > API copiar Project URL y Publishable key/anon public key a supabase-config.js.
3) Crear el primer usuario administrador desde Authentication > Users. Después asignar su perfil:
   update public.profiles set role='admin', active=true, username='administrador'
   where id='UUID_DEL_USUARIO';
4) Desplegar la función Edge admin-create-user. Configurar sus secrets SUPABASE_URL y SUPABASE_SERVICE_ROLE_KEY desde Supabase; la service_role solo vive en servidor.
5) La función permite al administrador crear usuarios por nombre y asignar rol editor o viewer.
6) La contraseña temporal implementada es 1234ICSSA. No se recomienda ni se permite asumir una contraseña de solo cuatro dígitos en un acceso remoto; cada usuario debe cambiarla por una personal.
7) El administrador es el único que puede registrar una nueva carga de base en base_imports. Los trabajadores no deben tener permiso para sustituir la base maestra.
8) La base patrimonial del Excel se importa desde la pantalla de administrador a public.assets, nunca se debe guardar dentro del repositorio público.

NOTA DE ESTADO:
El SQL y la función son la preparación del backend. Para activar el sistema todavía se requiere configurar el proyecto real, desplegar la función y conectar el frontend (URL + publishable key). No afirmar que ya hay usuarios o sincronización activa hasta probar login y cambios simultáneos con dos cuentas.
